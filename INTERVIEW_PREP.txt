RETINA DISEASE DETECTION USING DEEP LEARNING
Interview Prep, Project Explanation, and Q&A Bank

1) PROJECT SUMMARY

Project name:
Retina Disease Detection using Deep Learning

What this project does:
This project detects diabetic retinopathy / retinal disease from retinal fundus images and classifies them into severity classes. The repository includes training code, evaluation code, prediction code, a Streamlit demo, saved model files, and result artifacts such as a confusion matrix and evaluation CSV.

Important note:
This repository contains more than one experimentation path:
- A PyTorch training/evaluation pipeline in the root scripts.
- A Streamlit demo in binary/web that can load a TensorFlow/Keras .h5 model.

If an interviewer asks why there are two frameworks, say this:
"The repository evolved over time. I experimented with a PyTorch ResNet50-based training pipeline for research and evaluation, and I also built a Streamlit demo that can load a saved Keras model for a quick user-facing prototype. The goal was to show both model development and practical demo delivery."

2) HOW THE PROJECT WORKS

High-level flow:
1. Input retinal image or training dataset.
2. Preprocess images (resize, normalize, convert to tensor/array).
3. Train a deep learning classifier.
4. Validate the model and save checkpoints.
5. Run inference on new images.
6. Show predictions, probabilities, and visual output in Streamlit.
7. Save evaluation results and confusion matrix.

Model training path in the root code:
- model.py uses a ResNet50 backbone.
- Early layers are frozen to preserve generic visual features.
- The final fully connected layer is replaced with a custom classification head.
- The model predicts 5 classes.
- train.py uses CrossEntropyLoss, Adam optimizer, and StepLR scheduler.
- Checkpoints are saved so training can resume.
- evaluate.py loads the checkpoint, runs inference, prints classification metrics, and saves evaluation_results.csv and confusion_matrix.png.

Streamlit demo path:
- binary/web/smart_app.py loads a model file from MODEL_PATH or from a default models path.
- It preprocesses the uploaded image and runs model.predict.
- It displays the predicted label, confidence, and visual explanation.
- The app also tries to detect whether the uploaded image looks like a retina/fundus image.

3) MODEL ARCHITECTURE EXPLANATION

If asked "What architecture did you use?"
Answer:
"The main research pipeline uses ResNet50 as the feature extractor. I freeze the earliest layers and fine-tune the later layers with a custom classification head. That gives a good balance between general image features and domain-specific learning."

Key technical points:
- Backbone: ResNet50
- Transfer learning: yes
- Frozen layers: early convolution and batch norm layers
- Classifier head: Dropout -> Linear(512) -> ReLU -> Dropout -> Linear(num_classes)
- Loss: CrossEntropyLoss
- Optimizer: Adam
- Scheduler: StepLR
- Output: 5 classes

Why ResNet50?
- It is strong for image classification.
- Residual connections help gradient flow.
- It works well with transfer learning.
- It is a standard model that interviewers recognize.

Why transfer learning?
- Medical datasets are often limited in size.
- Training a deep model from scratch can overfit.
- Transfer learning improves convergence and accuracy.
- It reduces training time and compute cost.

Why freeze early layers?
- Early layers capture general features such as edges, textures, and color patterns.
- Freezing them reduces overfitting and keeps training stable.

Why CrossEntropyLoss?
- It is the standard loss for multi-class classification.
- It compares predicted class probabilities against true class labels.

Why Adam?
- It converges quickly.
- It works well as a first-choice optimizer.
- It handles sparse gradients and noisy updates better than plain SGD in many cases.

Why StepLR?
- It reduces the learning rate after a few epochs.
- This helps the model stabilize during later training.

Common SQL questions and sample answers:

Q1. What is the difference between WHERE and HAVING?
A: WHERE filters rows before grouping, while HAVING filters aggregated results after GROUP BY.

Q2. What is a JOIN?
A: JOIN combines rows from two tables based on related columns. INNER JOIN returns matching rows, LEFT JOIN keeps all rows from the left table, and so on.

Q3. What is GROUP BY used for?
A: It aggregates rows by a column or set of columns, such as counting patients per diagnosis.

Q4. What is a CTE?
A: A Common Table Expression is a temporary named result set used to make complex SQL queries easier to read.

Q5. What is the difference between UNION and UNION ALL?
A: UNION removes duplicates; UNION ALL keeps duplicates and is faster.

Q6. What are indexes?
A: Indexes improve search performance by allowing faster lookup, but they can slow down insert/update operations.

Q7. What is normalization?
A: Normalization reduces redundancy by splitting data into related tables.

Q8. What is a primary key?
A: A unique identifier for each row in a table.

Q9. What is a foreign key?
A: A column that references a primary key in another table.

Q10. How do you find duplicates?
A: Use GROUP BY with HAVING COUNT(*) > 1.

Q11. How do you get the top N records?
A: Use ORDER BY with LIMIT or TOP depending on SQL dialect.

Q12. What is a window function?
A: It performs calculations across a set of rows related to the current row, such as ROW_NUMBER() or running totals.

Q13. How do you handle NULLs?
A: Use IS NULL, COALESCE, CASE, and carefully design queries.

Q14. What is the difference between DELETE, TRUNCATE, and DROP?
A: DELETE removes rows, TRUNCATE removes all rows quickly, and DROP removes the entire table.

Q15. Give a simple SQL query to count class distribution.
A: SELECT diagnosis, COUNT(*) FROM retinal_images GROUP BY diagnosis;

Why interviewers ask SQL:
- To check data analysis skills
- To test whether you can prepare datasets
- To see if you understand pipeline data storage and reporting

10) MACHINE LEARNING / DEEP LEARNING QUESTIONS

Q1. What problem are you solving?
A: Automated retinal disease classification from fundus images.

Q2. Is it classification or regression?
A: Classification, because the model predicts one of several disease severity classes.

Q3. Why not train from scratch?
A: The dataset is relatively limited, so transfer learning is better.

Q4. How do you measure success?
A: Accuracy, class-wise precision/recall/F1, confusion matrix, and AUC.

Q5. Why is accuracy not enough?
A: Because class imbalance can make accuracy misleading. For medical problems, recall and F1 are often more important.

Q6. What is overfitting?
A: When the model memorizes training data and performs poorly on new data.

Q7. How do you reduce overfitting?
A: Freezing layers, dropout, better data augmentation, more data, regularization, early stopping.

Q8. What is a confusion matrix?
A: A table showing true classes versus predicted classes, useful for understanding misclassifications.

Q9. What is transfer learning?
A: Reusing a pretrained model on a new task.

Q10. What is fine-tuning?
A: Training some pretrained layers on the new dataset so the model adapts.

Q11. What is softmax?
A: A function that converts raw model outputs into probabilities across classes.

Q12. Why is class 3 sometimes weak in your results?
A: It likely has fewer samples or harder visual patterns. Severe classes are often underrepresented, which can reduce recall.

Q13. How would you improve performance?
A: Better data balancing, stronger augmentation, more training data, hyperparameter tuning, class weighting, and possibly a better backbone.

Q14. What is class imbalance?
A: When some classes have many more samples than others.

Q15. What is Cohen’s Kappa?
A: A metric that measures agreement between predicted and true labels beyond chance.
